# 01 架构设计

> **乾坤镜 = Agent 工程的纯数据底座 + 病历管理局 + 插件执行器**

---

## 一、设计理念

### 1.1 系统定位

乾坤镜（Mingjing）是一个**轻量级可观测性基础设施**，为 AI Agent 框架提供**无侵入的诊断与可观测能力**。通过热轨 JSONL + SQLite/MySQL 持久层，实现探针写入与数据归档的完全解耦。

**核心能力界定**：
- **0 LLM**：诊断规则全为确定性 SQL/YAML，不调用大模型
- **0 入侵**：monkey-patch 静默降级，不修改业务代码
- **0 写回**：仅观测不干预，不对目标系统执行任何写入操作
- **仅只读**：查询模块使用只读连接
- **0 联网**：Standalone 模式零网络依赖

> **157<!--M=disease_rules--> 条规则库**（~135 通用 + ~22 土行孙专属），但每个实例实际可触发数取决于适配器发射的事件类型。

## 二、核心铁律（违反即 P0）

| 铁律 | 说明 | 验证方式 |
|------|------|----------|
| **探针纯粹** | 探针只写 JSONL，不 import sqlite3/pymysql | AST 分析 |
| **唯一写入者** | 只有归档器可写入持久层 | 代码审查 |
| **零第三方依赖** | Standalone 模式仅 Python 标准库 | `pip list` |
| **Cluster 唯一依赖** | 仅 `pymysql` | `pip list` |
| **只读对外** | 查询模块使用只读连接 | 代码审查 |
| **三层解耦** | 探针不认识镜厅，镜厅不认识前端，前端不认识诊断 | 代码审查 |
| **底座轻量** | 底座不可拆卸 Python 部分 &lt;2000<!--M=budget_base--> 行 | `wc -l` |
| **零包袱** | 无历史遗留代码、无废弃文件 | 代码审查 |

## 三、设计哲学

| 原则 | 说明 |
|------|------|
| **观测而非干预** | 只记录、不修改业务逻辑 |
| **热轨解耦** | 探针写 JSONL，归档器异步消费，零并发锁 |
| **轻量优先** | 零 ORM、零第三方依赖、零配置可运行 |
| **证据链完整** | SHA-256 哈希链 + 完整性评分 |
| **双模式架构** | Standalone（零依赖）与 Cluster（MySQL）环境变量切换 |

## 四、架构概览

![乾坤镜架构图](./image/mingimage.png)

### 4.1 数据流

```
业务系统 → probe_uni.py → JSONL 热轨 → archiver.py → SQLite/MySQL
                                        ↓
                                  plugin_runner
                                        ↓
                              lit_lite / web_dashboard / tusunsun
```

**三层解耦**：
1. 探针 → 只知 JSONL，不知数据库
2. 归档器 → 只知 SQLite，不知插件
3. 前端 → 只知 data.json，不知诊断

### 4.2 代码量预算

| 层级 | 模块 | 行数 | 定位 |
|------|------|------|------|
| **核心底座** | archiver 族 + credential_vault + plugin_runner | ~1,350 | 唯一写入者 |
| **Cluster 扩展** | cluster_archiver + cluster_pool + bridge | ~463 | MySQL 批量归档 |
| **插件层** | lit_lite / web_dashboard / tusunsun | 无上限 | YAML 契约替换 |
| **适配层** | 16+ Python/JS/Go 适配器 | 无上限 | 每新增框架即新增节点 |

> **底座轻量**：核心不可拆卸部分 &lt;2000<!--M=budget_base--> 行，插件/适配器无预算限制。

## 五、双模式架构

| 维度 | Standalone | Cluster |
|------|------------|---------|
| 持久层 | SQLite | MySQL (InnoDB) |
| 额外依赖 | 零 | 仅 `pymysql` |
| 热轨 | 本地 JSONL | 本地 JSONL（网络解耦缓冲） |
| 归档器 | 单线程串行 | 连接池 + 批量写入 |
| 查询 | 读本地 SQLite | 读中央 MySQL |
| 规模 | 1-3 项目 / 单机 | 5-20+ 项目 / 分布式 |
| 切换 | `MING_MODE=standalone` | `MING_MODE=cluster` |

## 六、生态位定位

> 现有工具是"显微镜"（OTEL）或"体检中心"（New Relic），乾坤镜是"全科医生 + 处方单生成器"。

| 维度 | 乾坤镜 | 竞品差距 |
|------|--------|----------|
| **运行时内存** | RSS <40MB，零依赖 | 独一档 |
| **侵入性** | monkey-patch 静默降级 | 独一档 |
| **自动诊断** | 157<!--M=disease_rules--> 条规则库 | 竞品只输出指标不诊断 |
| **诊断-处方分离** | lit_lite → Web 目镜 → 人类/LIT审方 | 独一档 |
| **跨框架统一** | 16+ 适配器 | 竞品各自绑定 |
| **证据链审计** | SHA-256 哈希链 | 竞品无此功能 |
