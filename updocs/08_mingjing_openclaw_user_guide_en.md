# Mingjing Probe for OpenClaw

Mingjing is LIT 1.4's lightweight refraction array, providing non-intrusive observability for Agent frameworks via hot-rail JSONL + SQLite persistence. Contains 157 diagnostic rules.

## Prerequisites

- **Node.js** ≥ v22 (OpenClaw runtime)
- **Python 3** + `pyyaml` (Triage engine and Web panel)

```bash
pip3 install pyyaml
```

## Installation & Activation

### 1. Install via pip

```bash
pip install mingjing
```

### 2. Install the Probe Plugin

Copy the OpenClaw probe plugin to the extensions path:

```bash
cp -r /path/to/mingjing/extensions/openclaw ~/.openclaw/extensions/mingjing-probe
```

### 3. Enable the Probe Plugin

In `~/.openclaw/openclaw.json`:

```json
{
  "plugins": {
    "entries": {
      "mingjing-probe": {
        "enabled": true
      }
    }
  }
}
```

Or via CLI:

```bash
openclaw config set plugins.entries.mingjing-probe.enabled true
```

### 4. Restart Gateway

```bash
pkill -9 -f openclaw-gateway
openclaw gateway
```

> **Note**: Probe lazy-loads. First startup takes ~2-4 minutes. Look for `[mingjing-probe] Probe runtime started` in logs.

### 5. Start Archiver + Web Panel

```bash
# Archiver (background daemon, processes hot-rail events to SQLite)
cd /path/to/mingjing && MING_MODE=standalone python3 src/ming.py start --daemon

# Web panel (port 18088, auto-refresh, LAN-accessible)
cd /path/to/mingjing && python3 src/plugins/web_dashboard/server.py --daemon --host 0.0.0.0 --port 18088 --no-browser
```

Access `http://localhost:18088` or `http://<your-ip>:18088` for real-time data.

> **Resource profile**: Archiver + Web panel are independent daemons. **0 LLM calls, 0 network outbound.** Archiver ~40MB resident, Web panel optional + ~50MB. Probes auto-start/stop with OpenClaw (plugin mechanism), but archiver and Web panel **do not auto-start with OpenClaw**.

## ⚠️ First-time Setup Notes

**Mingjing is a passive observation tool. It cannot control your OpenClaw.** Events are generated by normal use of OpenClaw.

### Post-installation

1. **Confirm services are running** (Gateway, archiver, Web panel)
2. **Use OpenClaw normally for 5-10 minutes** — send some conversations, let the Agent read/write files or execute commands
3. **Open Web panel** → triage coverage card shows current diagnosable conditions

### Event Generation

| Event Type | When Generated |
|-----------|----------------|
| `llm_output` | Agent outputs text |
| `tool_call`, `error` | Agent calls tools (bash/read/write) |
| `agent_step_start/finish` | Agent completes a step cycle |
| `platform_snapshot` | Probe heartbeat (30s interval) |

### Events Captured (12 types)

| Event Type | Trigger | Data |
|-----------|---------|------|
| `llm_invoke` | LLM call completed | model, provider, tokens, latency_ms |
| `llm_output` | LLM output text | output_text, hash |
| `tool_call` | Tool call/execution | tool_name, status, execution_ms |
| `agent_event` | Agent runtime event | run_id, session_id, stream |
| `agent_step_start` | Step start | step_id, decision_summary |
| `agent_step_finish` | Step end | step_id, status, latency_ms |
| `platform_snapshot` | System heartbeat | RSS, FD count, disk free, CPU |
| `error` | Exception | error_type, error_msg |

## OTEL Channel (Optional Enhancement)

Mingjing collects data via the Hooks channel by default (probe plugin), **no extra config needed**. OTEL is an optional enhancement.

```bash
# Start Bridge
python src/otel_bridge.py
```

Bridge listens on `127.0.0.1:4319`. Python stdlib only, negligible memory.

## Configuration

In `~/.openclaw/openclaw.json` under `plugins.entries.mingjing-probe`:

| Config | Default | Description |
|--------|---------|-------------|
| `hotPath` | `~/.ming/hot` | Hot rail JSONL directory |
| `heartbeatIntervalMs` | `30000` | Heartbeat interval (ms) |
| `bufferSize` | `100` | Event buffer size (batch write threshold) |

## Daily Use

### Web Panel (Recommended)

Open `http://localhost:18088`. Key features:

- **System cards**: Event counts per system, last event time
- **Triage coverage**: Current diagnosable / total, by layer
- **Hash chain health**: Event integrity detection
- **Event waterfall**: Real-time event stream
- **Self-Health**: Probe health metrics

### CLI Usage

All commands in the project directory:

```bash
cd /path/to/mingjing
python3 src/cli.py <command>
```

#### Most Common

| Command | Purpose |
|---------|---------|
| `ming report` | **One-click report**: system status + event stats + recent diagnoses + triage coverage |
| `ming status` | Quick system online check |
| `ming dx list --days 1` | Last 24h diagnoses |
| `ming dx confirm` | Confirm diagnosis (mark as handled) |

## Diagnosis Rules Coverage

| Layer | Abbr | Diagnosable | Description |
|-------|------|-------------|-------------|
| System | SYS | 10 | System resources (memory/IO/FD/disk) |
| Probe | PRB | 7 | Probe health (emit rate/buffer/integrity) |
| Agent | AGT | 12 | Agent orchestration (steps/decisions/role/recovery) |
| Data Quality | DQT | 2 | Data quality (anomaly type/integrity) |
| Model | MDL | 10 | Model calls (tokens/latency/output/frequency) |
| Network | NET | 4 | Network (currently unreachable, needs HTTP hook) |
| Tool | TLT | 10 | Tool execution (time/hash/error/output) |

## Troubleshooting

| Issue | Check Method |
|-------|--------------|
| Probe not enabled | `openclaw config get plugins.entries.mingjing-probe.enabled` |
| No events 5min after Gateway | Lazy load, wait for `[mingjing-probe] Probe runtime started` |
| No hot rail files | `ls -la ~/.ming/hot/` (trigger Agent session first) |
| Archiver not running | `cat ~/.ming/.archiver_heartbeat` |
| Web panel empty | `curl http://localhost:18088/api/data.json` |
| Frequent alert banners | Click × to dismiss; same content won't repeat |

## Startup on Boot (Recommended)

Strongly recommended. Without it, archiver and Web panel won't start automatically with OpenClaw.

```bash
python3 src/ming.py service install
sudo systemctl enable ming-archiver ming-web
```

## Architecture Limitations

The following event types **cannot** be captured in the current OpenClaw environment:

- **NET network layer** (tcp_connected_ms, dns_resolved, status_code) — requires HTTP fetch hooking
- **BIZ business layer** (guardrail, milestone, plan, etc.) — OpenClaw doesn't produce business events
- **MEM memory layer** (memory_retrieve, memory_store) — OpenCode exclusive
