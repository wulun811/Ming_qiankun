## 二、诊断机制

### 2.1 分诊周期

- 默认 30 分钟一次（`MING_TRIAGE_INTERVAL_SEC=1800`）
- 可缩短至 30 秒用于密集监控
- Always-On 规则跳过分诊检查，每次归档 flush 时执行

### 2.2 评分算法

**单维度得分 = 该维度内所有匹配规则的**最大**置信度**。未匹配 = 0。

### 2.3 置信度计算

| 严重度 | 基础置信度 |
|--------|-----------|
| P0 | 90% |
| P1 | 85% |
| P2 | 75% |

**最终置信度 = 基础置信度 × triage_multiplier（分诊覆盖率）**

### 2.4 交叉验证突破 100%

当同一系统被 ≥2 个独立规则同时命中时，置信度提升至 **100%**。

原理：两个独立观测源确认同一症状，观测即确证。

| 场景 | 置信度 |
|------|--------|
| 单规则命中 | ≤90% |
| 独立规则交叉验证 | **100%** |

## 三、Always-On 实时告警（v0.11.9-alpha）

### 3.1 背景

分诊每 30 分钟运行一次，P0/P1 关键规则（如危险工具调用、Token 突增）的检测盲区不可接受。

### 3.2 机制

在规则定义中增加 `always_on: true`，诊断循环遇到此类规则时跳过 triage snapshot 检查，直接执行 SQL。

## 四、证据质量分级

| 等级 | 标准 | 代码可达 |
|------|------|----------|
| 1 = 基础 | 有事件 ID 或关键字段 | ✅ 最低可达 |
| 2 = 完整 | ≥ 1 事件 ID + ≥ 3 关键字段 | ✅ |
| 3 = 交叉验证 | ≥ 2 事件 ID + ≥ 6 关键字段 | ✅ |

> 等级 0（不完整）为理论定义，实际不会被产出。

## 五、语义门控

网络相关诊断**必须**在证据中包含 `layer_network` 字段，否则置信度上限为 50%，质量上限为 1。
